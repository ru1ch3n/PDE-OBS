## 2. What changed

### 2.1 Source (one facade file modified, one new module, one new tool)

| File | Change | Problem it fixes |
|---|---|---|
| `src/pdeobs/api/infer.py` | `PredictionBundle` gains `__post_init__`: identities must be a non-empty, unique string list matching the batch size; frame labels must be a non-empty, non-negative, strictly increasing integer vector whose length equals the number of predicted frames; an attached `InferenceInput` must carry the same identities in the same order | overlay 1 only made `load()` reject fractional or boolean frame labels; a bundle built in memory with `time_indices=[0.9]` could still be saved (the writer casts to int64, storing `[0]`) and then reloaded and scored as **valid** (a laundering path, see `review_audit/overlay2/probe-save-launders-float-frame.txt`). | `src/pdeobs/evidence.py` (new) | `python -m pdeobs.evidence plan / check / export`; schemas `pdeobs-evidence-bundle/v1`, `pdeobs-evidence-check/v1`, `pdeobs-evidence-error/v1` | links a paper table cell to resolved config, identity manifest, split receipt, final checkpoint, per-view contract, `predictions.h5` and strict score; hashes existing files and records missing ones as `blocked`, never fabricated; re-scores `predictions.h5` with the frozen `pdeobs-strict-v1` scorer and compares every per-identity value with `score.json`; checks the split receipt against the declared cohort (original500: 2000 records, 1800/200, 600/600/600, 67/67/66); `purpose_guard` refuses to label demo or smoke artifacts as paper evidence; `check` is read-only, `export` refuses an existing directory, references large files by hash by default, and refuses a demo bundle without `--allow-demo`; one JSON document on stdout, diagnostics on stderr, errors as one JSON line with `category`, `reason`, `next_step`; exit 0 complete, 3 incomplete, 2 failed or bad input |

## 3. Effect on the scientific protocol

**None.** The doctor reports the 143 protected science files hash-identical to the input baseline
(`review_audit/overlay2/final-doctor.json`). No substantive bug requiring a separate scientific patch
was found; the one gap (first row of 2.1) is in the API facade, and the fix only moves the existing
strict rules forward to construction time without changing any number, metric definition or the meaning
of any historical result. The semantic clarifications (this benchmark versus other protocols; the
general, paper, custom and stored namespaces; `preset=paper` is not a paper experiment; `easy train`
defaults to `split=all`; the key `random_3pct` may carry `ratio=0.5`; `mean` is the per-sample observed
mean; a strict `valid` is not provenance) were already in `docs/ai/PROTOCOLS.md` and `AGENTS.md` and
were not changed.

## 6. The boundary between software verification and research evidence

**Established this round:** interfaces report errors explicitly on bad input instead of coercing
silently; the demo, smoke and paper-evidence paths are separated in code and documentation; every link of
the evidence chain has an executable check and a passing record on real demo rows; the tree installs
non-editable outside the source directory and runs the small flows; the protected science files are
unchanged.

**Not established, and not establishable from this tree:** any paper cell (the tree holds no production
data, production checkpoints, prediction tensors or paper scores); any GPU execution; a clean
minimum-dependency install; the numerical-reference accuracy of the evaluated targets; the external
reproduction of any run. A `passed` from the evidence tool means only that the supplied files are mutually
consistent and the stored score follows from the stored arrays; it does **not** authenticate the origin
of data, weights or predictions.

## 7. Unfinished items and the minimal extra materials

Per claimed cell, the authors need to supply: (1) the `paper-row` output directory (`receipt.json`,
`row_resolved.json`, `checkpoints/training_config.json`, `training_completion.json`,
`checkpoints/last.pt`, `identity_manifest.json`, `split.json`, `evaluation/<view>/{contract.json,
predictions.h5, score.json}`); (2) the table-cell to run_id/attempt_id mapping; (3) the numerical-reference
report when reference-checked is claimed; (4) the shards needed for external reproduction (or an archive
that reproduces the same identities and checksums). With (1) and (2), `python -m pdeobs.evidence check`
runs without any code change; `plan` derives `purpose: paper-evidence` and `expected_identity_count: 200`
from cohort original500. Two substitutions are explicitly not made: the 200 formal TEST identities are
never replaced by two demo identities, and regenerated samples are never presented as the historical
evaluated data.
